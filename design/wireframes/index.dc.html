Structural decisions these wireframes assume

  1. Primary nav is five items — Assessments, Destinations, Services, Knowledge, About — with Assessments second per doc 01 §8. Fees, Concerns, Contact, Partners and the B2B page live in the footer. Eight top-level items don't fit 375px.
  2. The homepage hero contains a live first question, not a CTA to the assessment. Answering it deep-links into question 2 of ho-so-san-sang.
  3. The comparison table on mobile becomes destination tabs: criteria run down the page as persistent row labels; one destination column shown at a time, switched by tabs. Desktop keeps the full table with a sticky criteria column. No horizontal scroll of an 8-row table.
  4. Assessments are one question per screen at both widths. Desktop centres the question card rather than inventing a different layout — one flow to test and maintain.
  5. The not-ready result has no email gate anywhere on it. The emailed-explanation offer sits below the alternative direction, last.
  6. The ready result shows the paid service and fee range on the same screen, above the fold on mobile.
  7. Representatives render as verification rows — name, licence number, register link — never logo cards.
  8. US and Panama pages are built as gated shells: full structure, every claim inside a DRAFT — NOT CLEARED frame, so legal review is a walkthrough.
  9. Language toggle sits in the header at both widths; mid-assessment it preserves the current question index (flow 3).
  10. Closed programmes page is a dated table, newest first, each row carrying what replaced it or where demand went — the content asset from doc 01 §3.
